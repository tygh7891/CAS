# A5 독립 서버·한 화면 관제 GUI

## PC 터미널 — 실행

```bash
/usr/bin/python3 ~/CAS/cas/backup/operator_app/launch.py
```

이 PC의 시스템 Python(`/usr/bin/python3`)에는 PyQt5가 설치되어 있지만 `(ros)` 가상환경에는 없습니다. 위 명령은 가상환경 활성 여부와 관계없이 시스템 Python을 사용합니다. ROS 환경 설정이나 로봇 연결은 필요 없습니다. 서버와 GUI를 하나의 명령으로 시작합니다. GUI를 닫으면 내부 모의 작업을 취소하고 HTTP 서버도 종료합니다. 실행 중인 실물 구동·팀원 프로그램에는 명령하지 않습니다.

기본 포트가 사용 중이면:

```bash
/usr/bin/python3 ~/CAS/cas/backup/operator_app/launch.py --port 8766
```

## 사용자 확인 순서

1. 상단에 `MOCK · 실물 연결 잠김`, `서버 연결 정상`을 확인합니다.
2. `1차 시나리오 시작`을 누릅니다. 두 임무가 접수되고 로봇들이 대기점으로 이동합니다.
3. 오른쪽에서 진입권과 가상 점유를 구분해 확인합니다. 1번 통과 중 2번은 공유존 대기여야 합니다.
4. 전체 이탈 확인 → 권한 해제 → 다음 허가가 로그에 나타나는지 확인합니다.
5. 각각 B/A 도착 → 회전 → `작업 완료`·`정지 확인(모의)`를 확인합니다. 가상 로봇은 목적지에 남습니다.
6. 반복 시험은 `모의 세션 초기화` 후 시작합니다. 초기화는 가상 좌표·예약을 초기값으로 되돌리는 기능이며 출발점 복귀 임무가 아닙니다.
7. 개별 취소·전체 작업 취소를 시험할 수 있습니다. 점유 중 취소하면 예약·보류 사유를 유지하고 다른 로봇은 대기합니다. 새 시연 전 전체 작업을 취소한 뒤 초기화합니다.

`B 작업장 작업`은 1번만, `A 작업장 작업`은 2번만 실행합니다. 같은 세션에서 같은 로봇에 두 번 요청하지 못합니다. 작업 대기열·자동 할당은 아직 없습니다. 이미 끝난 로봇을 다시 출발시키려면 명시적으로 모의 세션을 초기화해야 합니다.

## 화면 구성

작업 명령 / 임시 가상 지도·로봇 위치·방향 / 두 로봇 상태 / 공유존 진입권·가상 점유·대기열 / 한국 시간 이벤트 로그. 실제 배터리·센서가 없으므로 수치를 꾸며 표시하지 않고 `—`로 표시합니다.

요청 접수와 작업 완료를 구분합니다. 현재 정지 확인과 회전 성공은 내부 모의 상태의 결과이며 실제 모터나 Nav2 검증이 아닙니다. 서버 연결이 끊기면 마지막 지도·상태임을 안내하고 명령 버튼을 비활성화합니다. 연결 단절 자체가 모의 서버의 실행 작업을 자동 취소하는 것은 아닙니다.

## 독립 구조와 현재 범위

- GUI: `gui.py`, HTTP 요청·화면 갱신만 담당합니다.
- HTTP 서버·작업 서비스: `service.py`, 로컬 요청 검증·중복 방지·세션·작업 관리·로그.
- 모의 연결 경계: `MockAdapter`. A3/A4 `Coordinator`를 재사용합니다.
- 시작·종료 관리: `launch.py`.
- MOCK만 실행 가능합니다. SIM_NAV2·REAL_NAV2를 선택하는 요청은 거부합니다. 실제 연결기, 외부 Worker 프로세스, 공통 설정 기반 전환은 A6·B·C에서 추가해야 합니다.
- 실제 지도 파일을 읽지 않습니다. 저장소의 map/ 폴더는 이번 구현에서 수정·추적하지 않았습니다.
- 실제 `/cmd_vel`·Nav2 Goal·Spin·Cancel을 발행하거나 ROS 노드를 만들지 않습니다.

## HTTP 계약 v0.1 (독립 구현용)

기본 주소: http://127.0.0.1:8765. 서버는 PC 내부에만 바인딩합니다. GUI에 전달된 실행 세션 토큰을 `X-CAS-Token` 헤더로 요구하며 외부 브라우저 CORS 접근은 허용하지 않습니다. 토큰은 Git에 저장하거나 로그로 출력하지 않습니다.

| 경로 | 방식 | 내용 |
|---|---|---|
| /api/v1/state | GET | mode·session_id·active·가상 로봇·공유존·이벤트 |
| /api/v1/tasks | POST | mission: scenario / work_B / work_A |
| /api/v1/cancel | POST | target: all / robot_1 / robot_2 |
| /api/v1/reset | POST | confirm: true, 진행 중인 작업이 없어야 함 |

POST 공통: request_id(고유 문자열), session_id(현재 state에서 확인), mode=MOCK. 접수 응답은 status=ACCEPTED이며 실제 완료는 state로 조회합니다. 동일 request_id·동일 내용은 기존 응답을 반환하고 재실행하지 않습니다. 같은 ID에 다른 내용은 409, 오래된 세션도 409로 거부합니다. 초기화 후 이전 요청 ID를 재전송해도 기존 응답만 반환하고 작업은 다시 시작하지 않습니다.

상태 조회는 5Hz, 내부 모의 tick은 20Hz입니다. 서버 원본 로그는 UTC ISO 시각, GUI 표시는 Asia/Seoul입니다. 로그는 operator_app/logs/*.jsonl에 저장되고 Git에서 제외됩니다. 메인/예비 제어권 인계와 실물 운용 인증 체계는 아직 미구현입니다.

## B1 — 수령 지도 보기·좌표 확인

### PC 터미널

기존 GUI 창을 닫은 뒤 실행합니다. 현재 `(ros)` 가상환경에도 PyQt5·PyYAML 설치가 확인되었습니다.

```bash
python3 ~/CAS/cas/backup/operator_app/launch.py \
  --map ~/CAS/map/fleet_world_new.yaml \
  --mask ~/CAS/map/fleet_x_keepout_new.yaml
```

- 지도 확인 모드에서는 모든 작업 명령을 GUI와 서버에서 차단합니다. 기존 모의 robot_1/2 위치·공유존을 새 지도에 겹쳐 쓰지 않습니다.
- 지도 클릭은 픽셀 중심의 map 좌표 확인일 뿐 목적지·출발점·공유존을 등록하지 않습니다.
- `마스크 흰 영역 강조`를 체크하면 원본 마스크의 밝은 픽셀을 청록색으로 겹쳐 표시합니다. 흰/검정의 통행 허용·금지 의미는 확인 전이며, Nav2 keepout에 적용하지 않습니다.
- 현재 B1 입력 이미지는 PGM(P2/P5)입니다. YAML은 image·resolution·origin·negate·threshold·mode를 검증합니다. 이미지 표시 자체는 원본 명도를 사용합니다.
- 좌표 변환은 이미지 상단 row=0과 map 좌표의 y방향 차이 및 원점 yaw를 반영합니다. 픽셀 (column,row) 중심은 image 좌표 (column+0.5,row+0.5)입니다.
- 두 수령 파일은 192×134px, 0.01m/px, origin=[-0.748,-1.041,0]입니다. 이미지 전체 좌표 범위는 x=[-0.748,1.172], y=[-1.041,0.299]m이며 주행 가능 범위와 다릅니다.
- 지도와 마스크의 크기·해상도·원점이 다르면 시작을 거부합니다. 원본은 읽기만 하며 Git에 자동 추가하지 않습니다.
- 이 PC의 map/은 사용자 제공 파일로 남겨두며 다른 PC에서는 파일을 별도로 전달받아 경로를 지정해야 합니다.

기존 임의 좌표 모의 시연은 `--map` 없이 실행하면 그대로 사용할 수 있습니다. 임시 지도에서 Nav2 시뮬레이션을 하려면 B2 가상 공간·센서·두 로봇 구성과 B3 좌표·Action 검증이 추가로 필요합니다.
