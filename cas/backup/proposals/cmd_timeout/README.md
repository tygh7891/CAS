# 속도 명령 타임아웃 수정안 및 시험

1번에 적용하고 바퀴를 띄운 저속 시험에서 자동 정지를 확인한 수정안입니다. 원본 패키지는 저장소 루트에서 변경하지 않고 이 폴더에 수정안·패치·검사 코드를 보관합니다.

- 대상: Pinky Pro 1의 pinky_bringup/bringup.py
- 원본: SOURCE.txt에 기록한 공식 커밋. 이전 점검에서 1번의 설치 파일과 해당 소스가 일치함을 확인했습니다. 적용 직전에 재확인이 필요합니다.
- cmd_vel_timeout 기본값: 0.5초. 유한한 양수만 허용합니다.
- 0.05초 주기 감시. 마지막 유효 명령의 수신 시각은 PC 시간이 아니라 로봇의 time.monotonic()으로 기록합니다.
- 수신 공백이 0.5초 이상이면 모터 속도 0을 전송합니다. 실제 실행 지연과 감속 시간이 추가되므로 0.5초 이내 물리적 정지를 보장하지 않습니다.
- 정지 전송 실패 시 다음 주기에 재시도합니다. 잘못된 NaN/Inf 명령도 정지를 요청합니다.
- 새 유효 명령이 들어오면 다시 주행할 수 있습니다. 비상정지 잠금 기능은 아닙니다.
- 향후 명령 송신기는 초기 기준 10Hz 이상 주기로 보내되 실제 네트워크 지연을 시험해야 합니다.
- 이 기능은 명령 스트림 중단을 감시합니다. 서버 장애 후 다른 송신기가 계속 명령을 보내는 경우를 감지하지는 않습니다.
- ROS 실행기, 프로세스, 운영체제 또는 모터 통신 자체가 멈추면 이 소프트웨어 감시도 정지를 보장하지 않습니다. 하드웨어 watchdog은 별도입니다.

## PC 터미널 — 로봇 없이 검사

```bash
python3 ~/CAS/cas/backup/proposals/cmd_timeout/test_timeout.py
```

실제 수정안의 콜백을 추출해 가상 모터와 시계로 검사합니다. 7개 검사 통과: 명령 전 무동작, 0.5초 경계, 수신에 따른 기한 갱신, 정지 실패 재시도, 비정상 명령, 정지 후 새 명령, 초기화 전 무동작. 문법 검사도 통과했습니다. 1번 하드웨어에서 0.02m/s 명령을 약 1초 발행 후 중단한 시험에서 마지막 명령 후 약 0.70초에 정지를 관측하고 육안으로 확인했습니다. 서버 네트워크 단절 및 로컬 Nav2 연동 정지는 아직 미검증입니다.

## 다른 장치에 적용할 경우의 절차

1. 핑키프로1 SSH 터미널: 실행 파일과 기존 수정 여부를 재확인하고 원본 백업.
2. 핑키프로1 SSH 터미널: 기본 구동 정상 종료, 수정안 적용 및 필요한 빌드.
3. 핑키프로1 SSH 터미널: 바퀴를 띄운 상태에서 기본 구동 재실행.
4. PC 터미널: 제한된 저속 명령 후 송신 중단. 로봇에서 정지 전송 로그 및 바퀴 정지를 확인.

모니터는 읽기 전용으로 유지합니다. 2번 로봇은 변경하지 않습니다.

## 주의: 실제 모터 시험 코드

`test_robot1.py`는 PC에서 실행하면 도메인 14의 실제 `/cmd_vel`에 명령을 발행합니다. 기본 검사에 포함하지 않으며 실행 전 대상·바퀴 지지·기존 제어기를 확인하고 별도 승인 후 사용합니다. 로그·개인 적용 기록은 Git에서 제외합니다.
