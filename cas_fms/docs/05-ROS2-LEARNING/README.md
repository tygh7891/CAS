## 지금까지 한 작업

**[프로젝트 구현·검증 기록]** 2026-11-11 기준

| 단계 | 결정과 결과 |
| --- | --- |
| 팀 문서화 | 3인 팀의 제안서를 프로젝트 계획, 관제 설계, 시험, 협업 기록으로 나눴다. 원문 요약과 후속 개발 결정을 구분했다. [문서 홈](../README.md) · [REQ-001](../03-COLLABORATION/REQUEST-LOG.md) |
| 작업 범위 | 내 담당은 PyQt FMS 화면과 서버다. 윤중호님과 각자 구현한 뒤 같은 맵·좌표에서 비교하기로 했다. 서버는 한 번에 한 대에만 교차로 진입권을 준다. [팀 개발 기준](../04-ENGINEERING/README.md) |
| 공유 맵 재사용 | 장윤호님이 공유한 `fleet_world_new`와 `fleet_x_keepout_new`를 사용했다. 기본 맵은 위치 추정과 장애물 위치에, X자 마스크는 진입 제한에 사용한다. [가상 시연 설명](../02-TESTING/LOCAL-DEMO.md) |
| 좌표 보간 시연 | 가상 Worker가 출발점과 목적지 사이의 위치를 계산해 보고하도록 만들었다. `1 → B`, `2 → A` 순차 통과와 정지, 출발점에서 다시 시작하는 흐름을 확인했다. |
| Gazebo 시연 | 공유 맵의 X자 교차로에서 왕복, 위치 보고 중단·복구, 교차로 내 작업 취소를 확인했다. 왕복에서는 진입권을 미리 받으면 무정차 통과하고, 접근이 겹치면 후순위만 대기한다. 두 로봇은 목적지와 출발점에서 각각 반 바퀴를 돌고 출발점에서 정지한다. [Gazebo 왕복 검증 결과](02-GAZEBO-FMS-LAB.md#gazebo-왕복-검증-결과) |
| FMS 화면 | 지도 옆에 교차로 진입권, 두 로봇의 상태와 최근 이벤트를 배치했다. 배터리는 카드에 잔량만 작게 표시하고 15초 동안 잔량이 갱신되지 않으면 수신 중단을 표시한다. [화면 사용법](../02-TESTING/LOCAL-DEMO.md#배터리와-센서) |
| 실물 읽기 전용 | 1번부터 SSH와 ROS 2 도메인을 확인했다. 엔코더 읽기 전용으로 두 대의 라이다·오도메트리·배터리·지도 위치가 노트북 FMS에 들어왔다. 지도와 위치 추정은 노트북에서 처리했다. [센서와 FMS 실습](03-PHYSICAL-READONLY-LAB.md) |
| 실물 지도·Nav2 | 두 대의 정지 상태에서 라이다와 지도를 대조했다. 2번의 두 비용 지도에서 마스크 수신을 확인했고, 1번 Nav2 활성화 확인은 남아 있다. 충전과 팀 사용 순서에 맞춰 점검 연결을 해제했다. [현장 검증 기록](05-FIELD-NAV2-CHECK.md#5-이번-실물-점검-기록) |
