## 코딩 표준

- 명명은 PEP 8을 따른다. 함수·변수·모듈은 `snake_case`, 클래스는 `PascalCase`, 상수는 `UPPER_SNAKE_CASE`를 쓴다. 들여쓰기는 공백 4칸이며, 줄 길이는 Ruff 포맷 기준인 88자를 목표로 한다. [PEP 8](https://peps.python.org/pep-0008/), [Ruff 포맷 문서](https://docs.astral.sh/ruff/formatter/)
- 공개 함수, 모듈 경계, 상태·메시지 객체에 타입을 명시한다. 유한한 상태는 `Enum`으로 표현하고, 읽기 전용으로 전달할 값은 필요한 경우 불변 `dataclass`로 표현한다. 좌표계와 단위를 인터페이스에 명시하고 시간 단위는 `timeout_s`처럼 이름에 드러낸다.
- 로봇 ID, Zone 좌표, Worker 주소와 도메인, 시간 기준은 공통 설정이나 해당 프로세스의 실행 설정에서 읽는다. HTTP 경계에서 필수 필드와 값을 검증한다. 예상 가능한 거부·실패를 명시적으로 반환해 호출자와 GUI가 구분할 수 있게 한다.
- 함수와 모듈은 한 가지 책임으로 유지한다. 기존 규칙은 해당 책임을 가진 모듈에서 재사용하고, 공개 인터페이스의 문서와 주석에는 호출 조건이나 실패 의미처럼 코드만으로 알기 어려운 정보를 적는다.

## 코드 변경 검증

첫 Python 코드 변경에서 Ruff 설정과 pytest 실행 방법을 `cas_fms/`에 마련한다. 이후 `cas_fms/`에서 `ruff check .`, `ruff format --check .`, 변경 범위의 `python -m pytest`를 실행한다. 검사 범위는 FMS 코드에 맞춘다.

도메인 규칙은 로봇 없이 시험한다. 동시 요청에 허가가 한 건만 나가는지, 중복 요청과 오래된 해제 요청이 진입권을 바꾸지 않는지, 진입 전 해제가 방지되는지, 안전한 이탈 후 다음 로봇에 권한이 넘어가는지 확인한다. 위치를 확인할 수 없을 때는 대기를 유지해야 한다.

통신 변경은 Mock Worker로 로봇 ID별 상태와 허가된 로봇의 명령 전달을 확인한다. 메인·예비 전환을 연동할 때는 제어권이 없는 서버의 요청이 거부되는지 확인한다. GUI 변경은 통신 지연 중에도 화면이 응답하고 대기·통과·회전·연결 끊김을 구분하는지 확인한다.

실물에서는 [시험 계획의 S2](../02-TESTING/TEST-PLAN.md)를 적용해 순차 통과를 확인하고, CAS A1 시나리오에서는 두 로봇이 각 목적지에서 회전 후 정지·대기한 시점에 작업이 완료되는지 확인한다. 하드웨어나 환경 제약으로 미실행한 검증은 결과에 표시한다.
