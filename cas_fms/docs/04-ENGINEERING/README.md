# FMS 팀 개발 기준

[문서 홈](../README.md) · [프로젝트 작업 지침](../../AGENTS.md)

이 기준은 `cas_fms/`에서 FMS 서버·PyQt GUI를 구현하고 로봇별 Worker와 연동하는 팀원과 코딩 에이전트에 적용한다.

| 문서 | 적용할 내용 |
| --- | --- |
| [FMS 설계 패턴과 모듈화 기준](FMS-ARCHITECTURE.md) | CAS A1 연결 구조, 서버·GUI·Worker 책임, 경량 DDD, MVP, HTTP 어댑터, 진입권과 작업 상태 전이 |
| [Python 코딩 표준과 검증](PYTHON-STANDARDS.md) | 코드 스타일과 타입, 설정·오류 처리, Ruff·pytest, 변경 범위에 맞는 검증 |

FMS 개발 담당 두 사람은 각자의 브랜치에서 서버·GUI를 독립적으로 구현하고, 구현 후 결과를 비교한다. `cas_fms`는 CAS A1의 연결 구조를 바탕으로 자체 API와 설정을 정의하고, 가상 Worker로 서버와 GUI를 먼저 검증한다. 공통 인터페이스가 필요해지면 비교 결과를 바탕으로 합의한다.

비교할 때는 두 구현에 동일한 지도, 대기점·목적지, 작업 입력과 판정 조건을 적용한다. 한 대씩 교차로를 통과하는지, 각 로봇이 목적지에서 회전 후 정지하는지, GUI가 작업 완료 시점을 정확히 표시하는지 본다. 실물 시험에서는 한 번에 한 구현만 로봇을 제어한다. [시연 및 시험 기록](../02-TESTING/TEST-PLAN.md)

Codex로 작업할 때는 `cas_fms/`를 작업 위치로 열고 [AGENTS.md](../../AGENTS.md)를 적용한다. 제안서에 있던 구조와 현재 구현 기준이 다르면 이 폴더의 기준을 적용한다.
