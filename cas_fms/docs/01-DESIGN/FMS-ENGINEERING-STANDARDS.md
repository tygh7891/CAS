[문서 홈](../README.md) · [원문 관제 설계 요약](FLEET-DESIGN.md) · [프로젝트 작업 지침](../../AGENTS.md)

## 적용 범위

팀이 선택한 **PyQt**로 FMS GUI를 만든다. 서버는 Python 기반 ROS 2 관제 노드로, GUI는 그 상태를 구독하고 운영자 요청을 보내는 별도 프로세스로 구성한다. 서버는 창의 실행 여부와 독립적으로 동작한다. 첫 구현에서 대상 장비의 Python·ROS 2 환경과 호환되는 PyQt 버전을 확인해 의존성에 명시한다.

교차로 한 곳과 Pinky Pro 두 대를 대상으로 상태 관제와 순차 통과부터 구현한다. 상세 모듈은 기능이 필요해지는 순서에 맞춰 추가한다. 로봇의 Nav2 실행과 로컬 정지는 Robot Agent 측과 인터페이스를 합의한다.

### 코드 구성

초기 코드에서 아래 책임 경계를 사용한다. 필요한 모듈부터 만들고, 이름은 실제 ROS 2 패키지 구조와 맞춘다.

| 프로그램 | 영역 | 책임 |
| --- | --- | --- |
| FMS 서버 | `domain` | Zone, 유효 예약, 대기 요청과 전이 규칙 |
| FMS 서버 | `application` | 진입 요청, 위치 갱신, 이탈 처리와 명령 연결 |
| FMS 서버 | `adapters/ros2` | ROS 2 노드, 메시지 변환, 상태 발행 |
| FMS GUI | `views` | PyQt 창·위젯과 표시 |
| FMS GUI | `presentation` | Presenter와 표시용 상태 |
| FMS GUI | `adapters/ros2` | 서버 상태 구독과 운영자 요청 전송 |

서버의 유스케이스는 도메인에 의존한다. 실행 시 필요한 통신과 설정은 진입점에서 연결한다. GUI는 서버 내부 객체에 접근하지 않고 ROS 2 계약으로 통신한다. 교체가 필요한 경계부터 인터페이스를 둔다.

## DDD 용어와 진입권 규칙

- **Zone**은 공통 지도에서 진입을 관리하는 교차로 구역이다. Zone이 유효 예약과 대기 요청의 일관성을 관리하는 단위다.
- **예약(Reservation)**은 로봇 한 대가 Zone에 진입할 수 있는 권한이다. 로봇 ID, Zone ID, 예약 ID로 식별한다. **점유(Occupancy)**는 로봇이 실제로 Zone 안에 있다는 관측이다. 서버는 허가 시점부터 권한을 보유한 것으로 다루고, 실제 진입·이탈은 위치로 확인한다.
- **대기 요청**은 Zone에 진입할 차례를 기다리는 요청이다. 최초 구현의 기본 순서는 서버에 도착한 유효 요청 순서다. 요청 ID로 재전송을 구분하고, 같은 ID에는 현재 처리 결과를 반환한다. 처리된 요청을 재전송해도 새 진입권은 생기지 않는다.
- **진입권 부여, 이탈 확인 및 해제, 다음 허가 결정**은 하나의 직렬 처리 경로에서 처리한다. 첫 서버 구현은 상태 변경 콜백을 단일 스레드 실행기에 두고, ROS 2 응답은 비동기로 처리한다. 예약이 바뀐 뒤 도착한 예전 응답은 현재 예약 ID와 대조한다.
- 진입권을 받은 로봇에만 교차로 통과를 지시한다. 진입을 확인한 뒤 로봇의 몸체 전체가 경계 밖으로 나오면 해제한다. 진입 전에 취소한 경우에는 통과 명령이 종료되고 로봇이 구역 밖에 정지했는지 확인한 뒤 해제한다.
- 위치가 오래됐거나 통과 명령의 처리 결과가 불확실하면 다음 허가를 보류한다. 서버 재시작 후에는 이전에 허가된 통과 명령이 남아 있는지와 현재 점유를 확인한 뒤 새 진입을 허가한다.

## PyQt 실행 규칙

- Qt 위젯의 생성과 변경은 메인 스레드에서 한다. ROS 2 통신은 별도 작업 스레드에서 처리하고, 화면 갱신에는 불변 상태 값과 큐 연결 신호를 사용한다.
- 버튼은 요청을 보낸 뒤 서버의 응답과 상태 갱신을 표시한다. 처리 중, 실패, 연결 끊김을 화면에서 구분한다. 이전에 받은 진입 허가는 서버 연결이 끊겼을 때 현재 상태로 표시하지 않는다.
- 서버는 화면을 띄우지 않고 실행할 수 있어야 한다. 종료할 때는 구독과 실행기를 정리하고 작업 스레드를 종료한다. [Qt 스레드와 객체 문서](https://doc.qt.io/qt-6/threads-qobject.html)

## Python 코딩 표준

- 명명은 PEP 8을 따른다. 함수·변수·모듈은 `snake_case`, 클래스는 `PascalCase`, 상수는 `UPPER_SNAKE_CASE`를 쓴다. 들여쓰기는 공백 4칸이며 줄 길이 기준은 Ruff 포맷에 맞춰 88자로 한다. [PEP 8](https://peps.python.org/pep-0008/), [Ruff 포맷 문서](https://docs.astral.sh/ruff/formatter/)
- 공개 함수, 모듈 경계, 상태·메시지 객체에 타입을 명시한다. 유한한 상태는 `Enum`, 전달용 값은 필요한 경우 불변 `dataclass`로 표현한다. 좌표 프레임과 단위는 인터페이스에 명시하고, 시간 단위가 중요한 값은 `timeout_s`처럼 이름에 드러낸다.
- 로봇 ID, Zone 좌표, 네임스페이스, 시간 기준은 ROS 2 파라미터나 실행 설정에서 받는다. 외부 입력은 경계에서 검증하고, 처리 가능한 오류는 구체적으로 다뤄 호출자와 화면에 전달한다.
- 첫 Python 코드 변경부터 팀원이 같은 검사 설정을 쓸 수 있게 구성한다. 코드 변경 후 `ruff check .`, `ruff format --check .`, 해당 범위의 `python -m pytest`를 실행한다.
