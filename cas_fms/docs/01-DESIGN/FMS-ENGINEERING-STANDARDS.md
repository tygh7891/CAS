# FMS 구현 기준

[문서 홈](../README.md) · [원문 관제 설계 요약](FLEET-DESIGN.md) · [프로젝트 작업 지침](../../AGENTS.md)

## 적용 범위

FMS는 윤중호님의 연결 방식을 적용한다. **PyQt GUI는 중앙 Python 서버에 HTTP+JSON으로 접속**하고, 중앙 서버는 같은 PC에서 실행되는 **로봇별 Worker 두 개**와 HTTP+JSON으로 통신한다. GUI는 등록된 작업의 실행을 요청하고 서버 상태를 표시한다. 서버는 GUI와 독립적으로 작업 순서와 교차로 진입권을 관리한다. Worker는 각 로봇의 ROS 2 도메인에서 Nav2 명령을 전달하고 위치·속도·실행 결과를 서버에 보고한다. [CAS A1 팀 연결 규칙 초안](https://docs.google.com/document/d/1M0vVh-dudI4m3VpH1n6Jo7gHRPfLjpf_VuqwgzxB0Xg/edit?tab=t.0#heading=h.l6risryh22t0)

1차 시연은 `robot_1`의 **1→B**, `robot_2`의 **2→A**, 공유 Zone 순차 통과, 목적지 제자리 회전 후 정지·대기까지다. 복귀는 2차 범위로 둔다. 첫 구현에서 대상 PC의 Python 환경과 호환되는 PyQt 버전을 확인해 의존성에 명시한다.

## 디자인 패턴과 모듈 경계

| 구분 | 패턴 | 적용 규칙 |
| --- | --- | --- |
| 서버의 도메인 | 경량 DDD와 명시적 상태 전이 | Zone과 예약의 상태 및 허용 전이를 한곳에 둔다. 표준 Python으로 작성하고 Qt·ROS 2·파일 I/O 의존성을 두지 않는다. |
| 서버의 유스케이스 | 애플리케이션 서비스 | 진입 요청, 로봇 상태 수신, 이탈 확인을 처리한다. 도메인 판단을 호출한 뒤 그 결과를 바탕으로 통과 명령이나 관제 상태를 전달한다. |
| 서버·GUI의 통신 경계 | 어댑터 | HTTP+JSON 요청·응답과 내부 타입의 변환을 경계에 둔다. ROS 2 메시지와 Nav2 Action 연결은 Worker에서 처리한다. |
| PyQt GUI | MVP의 View와 Presenter 분리 | View는 입력과 표시를 담당한다. Presenter는 서버 상태를 화면 표시용으로 변환하고 입력을 서버 요청으로 연결한다. 진입권은 서버 응답과 상태 갱신에 따라 표시한다. |

### 코드 구성

초기 코드에서 아래 책임 경계를 사용한다. 필요한 모듈부터 만들고, Worker 쪽 경계는 협업 인터페이스로 사용한다.

| 프로그램 | 영역 | 책임 |
| --- | --- | --- |
| FMS 서버 | `domain` | Zone, 유효 예약, 대기 요청과 전이 규칙 |
| FMS 서버 | `application` | 진입 요청, 위치 갱신, 이탈 처리와 명령 연결 |
| FMS 서버 | `adapters/http` | GUI용 API, Worker용 HTTP 클라이언트, JSON 변환 |
| FMS GUI | `views` | PyQt 창·위젯과 표시 |
| FMS GUI | `presentation` | Presenter와 표시용 상태 |
| FMS GUI | `adapters/http` | 중앙 서버 상태 조회와 운영자 요청 전송 |
| 로봇별 Worker | HTTP ↔ ROS 2 경계 | 각 도메인에서 Nav2 Action 실행·취소, 로봇 상태와 결과 보고 |

서버의 유스케이스는 도메인에 의존한다. 실행 시 필요한 통신과 설정은 진입점에서 연결한다. GUI는 중앙 서버의 HTTP API를 사용한다. 교체가 필요한 경계부터 인터페이스를 둔다.

## 연동 계약

| 항목 | 적용 기준 |
| --- | --- |
| 로봇 구분 | `robot_1`은 ROS 2 도메인 `14`, `robot_2`는 `30`을 사용한다. 도메인과 연결 정보는 Worker 실행 설정에서 읽는다. |
| 명령과 결과 | 요청은 `request_id`, `task_id`, `robot_id`로 추적한다. 서버가 Worker에 보내는 명령은 `NAVIGATE`, `SPIN`, `CANCEL`이다. `ACCEPTED`는 접수이고 `SUCCEEDED`는 성공 결과다. 로봇당 활성 작업은 하나로 제한한다. |
| 보고 상태 | `robot_id`, `task_id`, `task_state`, `phase`, `pose`, `battery_percent`, `pose_age_s`, `error_code`를 사용한다. `task_state`는 `IDLE`, `RUNNING`, `SUCCEEDED`, `FAILED`, `CANCELING`, `CANCELED`로 구분한다. `phase`는 `TO_WAIT`, `WAITING_ZONE`, `CROSSING`, `TO_GOAL`, `SPINNING`을 기준으로 한다. 위치·배터리 등 미수신 값은 `null`로 표시한다. |
| 공통 설정 | `scenario.yaml`에 연결 정보, `map_id`, 목적지, 대기점, 공유 Zone 경계와 회전 조건을 둔다. 위치는 공통 `map` 기준의 m·rad를 사용한다. 지도 정합과 좌표를 확인한 뒤 실물 작업을 허용한다. |
| 메인·예비 연동 | 공통 Worker를 사용하고 한 번에 한 서버만 제어권을 가진다. 이전 작업의 취소와 실제 정지를 확인한 뒤 수동으로 제어권을 넘기고, 제어권이 없는 서버의 실행 요청은 거부한다. |

API 경로·주소·포트·인증, 설정 파일의 세부 형식과 위치, 실제 좌표는 팀 연동 시 확정한다. 회전은 Nav2 Spin Action을 우선 검토한다. 각도·속도·허용오차와 위치 최신성 기준은 장비에서 확인한 뒤 확정한다. [CAS A1 권장안 및 우선 합의 항목](https://docs.google.com/document/d/1M0vVh-dudI4m3VpH1n6Jo7gHRPfLjpf_VuqwgzxB0Xg/edit?tab=t.0#heading=h.lrrc2k2tdoyo)

## DDD 용어와 진입권 규칙

- **Zone**은 공통 지도에서 진입을 관리하는 교차로 구역이다. Zone이 유효 예약과 대기 요청의 일관성을 관리하는 단위다.
- **예약(Reservation)**은 로봇 한 대가 Zone에 진입할 수 있는 권한이다. 로봇 ID, Zone ID, 예약 ID로 식별한다. **점유(Occupancy)**는 로봇이 실제로 Zone 안에 있다는 관측이다. 서버는 허가 시점부터 권한을 보유한 것으로 다루고, 실제 진입·이탈은 위치로 확인한다.
- **대기 요청**은 Zone에 진입할 차례를 기다리는 요청이다. 최초 구현의 기본 순서는 서버에 도착한 유효 요청 순서다. 요청 ID로 재전송을 구분하고, 같은 ID에는 현재 처리 결과를 반환한다. 처리된 요청을 재전송해도 새 진입권은 생기지 않는다.
- **진입권 부여, 이탈 확인 및 해제, 다음 허가 결정**은 서버의 한 경로에서 직렬로 처리한다. Worker의 네트워크 응답을 기다리는 동안 상태 처리 경로가 멈추지 않도록 한다. 늦게 도착한 응답은 해당 작업과 현재 예약에 속하는지 대조한다.
- 진입권을 받은 로봇에만 교차로 통과를 지시한다. 진입을 확인한 뒤 로봇의 몸체 전체가 경계 밖으로 나오면 해제한다. 진입 전에 취소한 경우에는 통과 명령이 종료되고 로봇이 구역 밖에 정지했는지 확인한 뒤 해제한다.
- 위치가 오래됐거나 통과 명령의 처리 결과가 불확실하면 이탈 판정과 다음 허가를 보류한다. 같은 관측을 재전송해도 원본 관측 시각을 갱신하지 않는다. 서버 재시작 후에는 이전 통과 명령과 현재 점유를 확인한 뒤 새 진입을 허가한다.
- 목적지 도착 후에는 회전 단계로 넘어간다. 회전 성공과 정지를 확인한 뒤 작업 완료로 표시한다. 취소는 접수와 완료를 구분하고 Action 결과와 실제 정지를 확인한 뒤 완료 처리한다.

## PyQt 실행 규칙

- Qt 위젯의 생성과 변경은 메인 스레드에서 한다. HTTP 통신은 화면 이벤트 루프를 막지 않도록 비동기로 처리한다. 별도 작업 스레드를 쓰는 경우, 화면 갱신에 필요한 불변 상태 값을 큐 연결 신호로 전달한다.
- 버튼은 요청을 보낸 뒤 서버의 응답과 상태 갱신을 표시한다. 처리 중, 실패, 연결 끊김을 화면에서 구분한다. 이전에 받은 진입 허가는 서버 연결이 끊겼을 때 현재 상태로 표시하지 않는다.
- 서버는 화면을 띄우지 않고 실행할 수 있어야 한다. GUI 종료 시 남은 네트워크 요청과 작업 스레드를 정리한다. [Qt 스레드와 객체 문서](https://doc.qt.io/qt-6/threads-qobject.html)

## Python 코딩 표준

- 명명은 PEP 8을 따른다. 함수·변수·모듈은 `snake_case`, 클래스는 `PascalCase`, 상수는 `UPPER_SNAKE_CASE`를 쓴다. 들여쓰기는 공백 4칸이며 줄 길이 기준은 Ruff 포맷에 맞춰 88자로 한다. [PEP 8](https://peps.python.org/pep-0008/), [Ruff 포맷 문서](https://docs.astral.sh/ruff/formatter/)
- 공개 함수, 모듈 경계, 상태·메시지 객체에 타입을 명시한다. 유한한 상태는 `Enum`, 전달용 값은 필요한 경우 불변 `dataclass`로 표현한다. 좌표 프레임과 단위는 인터페이스에 명시하고, 시간 단위가 중요한 값은 `timeout_s`처럼 이름에 드러낸다.
- 로봇 ID, Zone 좌표, Worker 주소와 도메인, 시간 기준은 공통 설정이나 해당 프로세스의 실행 설정에서 받는다. 외부 입력은 경계에서 검증하고, 처리 가능한 오류는 구체적으로 다뤄 호출자와 화면에 전달한다.
- 첫 Python 코드 변경부터 팀원이 같은 검사 설정을 쓸 수 있게 구성한다. 코드 변경 후 `ruff check .`, `ruff format --check .`, 해당 범위의 `python -m pytest`를 실행한다.
