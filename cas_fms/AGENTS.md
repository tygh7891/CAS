# Pinky Fleet Coordinator 작업 지침

이 지침은 프로젝트 루트 아래의 FMS 구현, 수정, 리뷰에 적용한다. FMS 작업을 시작하기 전에 [FMS 구현 기준](docs/01-DESIGN/FMS-ENGINEERING-STANDARDS.md)을 읽고 적용한다. 기능 범위와 우선순위는 [프로젝트 계획](docs/00-PROJECT/PROJECT-PLAN.md)을 참고한다.

## 구현 규칙

- GUI는 PyQt로 만들고, 서버의 관제 규칙은 Qt와 ROS 2에서 분리된 Python 코드로 작성한다. 서버를 진입권의 유일한 관리 주체로 둔다. GUI는 서버 상태를 표시하고 운영자 요청을 전달한다.
- 서버 코드는 도메인, 유스케이스, ROS 2 어댑터로 나눈다. GUI는 화면, 프레젠터, 통신 어댑터로 나눈다. 패키지와 외부 의존성은 실제 기능에 필요한 시점에 추가한다.
- 하나의 Zone에는 동시에 하나의 유효한 진입권만 존재해야 한다. 모든 진입권 상태 변경을 서버의 한 실행 경로에서 순차적으로 처리한다. 안전한 이탈을 확인할 수 없으면 새 진입을 보류한다.
- Qt 위젯은 메인 스레드에서만 접근한다. ROS 2 통신과 대기 작업은 화면 이벤트 루프 밖에서 처리하고, 화면에 필요한 값은 큐 연결 신호로 전달한다.
- Python은 PEP 8의 명명·들여쓰기 규칙, Ruff 포맷·린트, 공개 함수와 모듈 경계의 타입 힌트를 적용한다. 상세 기준과 검증 명령은 구현 기준 문서를 따른다.

## 변경 검증

- Python 코드를 처음 추가할 때부터 Ruff와 pytest 실행 방법을 마련한다. 이후 코드 변경마다 `ruff check .`, `ruff format --check .`, 변경 범위의 pytest를 실행한다.
- 진입권 규칙을 바꾸면 중복 요청, 동시 진입 요청, 이탈 후 인계, 위치 확인 불가에 대한 관련 검증을 수행한다. 장비나 실행 환경 제약으로 확인하지 못한 항목은 작업 결과에 명시한다.
- Google Docs의 원문 요약과 팀에서 정한 구현 기준은 별도 제목이나 문서로 구분한다.
